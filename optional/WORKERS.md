# 子对话调度协议（主对话专用 SOP）

> 本对话是主对话（编排者 + 学习者）。挖洞工作由四个注册子代理承担：
> `bounty-recon`（侦察官，阶段0–2）、`bounty-deepdive`（深挖官，阶段3–4）、`bounty-scanner`（扫描官，阶段5–6）、`bounty-attacker`（攻击手，阶段7–8）。
> 角色定义文件在 `{agents目录}/`；若该类型在会话中不可用，用 general-purpose 子代理并把对应文件正文注入其 prompt。

## 轮次结构（每次开一轮挖洞）
1. **学习同步**：确认 PLAYBOOK.md / VULN_DB.md 为最新（cron 每日已更新）。
2. **第一波（阻塞）**：派生 `bounty-recon`，等它完成（阶段3 起依赖它的产物）。
3. **第二波（并行）**：recon 完成后，**同时**派生 `bounty-deepdive` 与 `bounty-scanner`。
4. **回收**：汇总两路结果，主对话亲自执行阶段6（triage 汇总）与阶段7-8（攻击面建模/假设清单 → 定向攻击 + 报告生成；也可派生 bounty-attacker 承担）。
5. **学习回写**：从 worker 回复中提取「经验反馈」→ 合并进 PLAYBOOK.md 第5节（每轮最多3条、去重）；新组件/CVE 情报 → 追加进 VULN_DB.md。
6. **简报**：向用户汇报本轮成果 + 手册/漏洞库变更摘要。

## 派生消息模板（每个 worker 的 prompt 必含）
```
角色：你是挖洞流水线的<bounty-XXX>子代理。
先读：{本技能目录}/PLAYBOOK.md 与 VULN_DB.md（最新版，开工前必读）；bounty-attacker 另读 HACKER_MINDSET.md（攻击者思维，阶段7/8 必读）。
参数：target=<目标> scope=<范围文件> output_dir=<本轮输出目录> 你负责的阶段=<N–M>
铁律重申：范围外资产零请求；长命令加 timeout；失败写 errors.log 继续；不越界做其他阶段的活。
收工要求：最终回复给出 ①产物清单（路径+行数）②关键发现摘要 ③「经验反馈」段落（[有效]/[踩坑]/[建议] 各条）。
过程留痕：开工时在 {output_dir}/pipeline_log.md 追加一行开始记录，收工时追加一行结束记录（时间 + 阶段 + 一句话结果）；该日志供用户随时查看全局进度。
```

## 经验反馈格式（从 worker 回复中提取）
- `[有效]`：好用的命令/参数/技巧 → 固化进 PLAYBOOK 对应章节
- `[踩坑]`：失败的尝试与原因 → 写成避坑条目
- `[建议]`：对流水线/调度结构的改进想法 → 主对话评估后实施

## 维护规则
- PLAYBOOK.md 是"当前最优打法"，保持精炼：每轮最多新增 3 条，重复/被证伪的删除。
- VULN_DB.md 是"漏洞情报日志"，只追加不删除。
- 用户未提供授权目标/范围时，**不得派生任何 worker**。

## 上下文纪律（防止上下文耗尽，所有角色遵守）
- 大文件（*.jsonl、子域/URL 清单、扫描输出）一律用 grep / jq / awk 处理，**禁止 cat 全文**进任何回复。
- worker 最终回复 ≤ 60 行：产物清单 + TOP10 级摘要 + 经验反馈；禁止粘贴原始工具输出。
- 主对话引用产物只写文件路径，不复读内容；报告从 JSONL 用脚本抽字段生成。
- 主对话每轮收工只保留三件事：worker 摘要、经验回写、对用户的一行简报。
- VULN_DB.md 条目超过 200 行时由主对话归档：旧条目移入 VULN_DB_ARCHIVE.md，正文保留"近期高价值方向 + 组件索引"。
- 新会话接任主对话的方法：依次读 WORKERS.md → SKILL.md → PLAYBOOK.md → VULN_DB.md 即可恢复全部编排能力。
